# Bounded lifecycle reconciliation candidate (C3a)

Engineering issue #13; planning revision `ca186f025d021c5e2cfe849c05cafcc3f20ada57`. This is an additive, default-off CMS worker. It does not remove `ListPage` global reconciliation or the per-page authority check. C3b is conditional on deployed freshness and cost evidence, including independent wake coverage while CMS has no replicas.

`RECORDING_LIFECYCLE_RECONCILE_ENABLED=true` would start the existing server worker at startup and every 30 seconds. Each tick handles at most 100 bindings in 10 seconds. A 15-second PostgreSQL lease fences concurrent/restarted owners. Due repair work receives at most 20 records and two seconds; normal stable UUID keyset traversal receives the remaining record budget and seven seconds. No database transaction spans Asset HTTP. Existing complete lifecycle DTO validation and projection version/deletion/binding fences remain authoritative.

Migration 113 adds a singleton checkpoint owned by CMS: cursor, cycle timestamps, bounded retry state and at most 1,000 repair bindings / 512 KiB JSON. The existing schema has no durable lifecycle cursor. This is not a generic queue or Asset change log. Projection writes and cursor/repair changes commit in the same transaction; lease token and expiry are checked before and after applying the projection.

All nondeleted, nonterminal package bindings participate, including unready and locally expired recordings. Traversal wraps at the end; inserts behind the current key enter the next cycle. A successful full-cycle timestamp is recorded only with no outstanding repair obligations. Missing items never imply deletion. Global authority failures retain the cursor and back off from 30 to 240 seconds. Invalid/missing bindings and permanent projection constraints retain the range for three attempts, then persist repair obligations atomically before advancing. Repair uses singleton requests because the existing Asset endpoint returns whole-batch 404. Full recording/package identity distinguishes a rebind from an old obligation; only an authoritative local binding change/deletion/terminal state retires the old obligation. Capacity exhaustion returns an error and retains the previous checkpoint rather than discarding work.

The checkpoint remains inert after disabling the worker. Rolling back to the previous CMS artifact preserves the old synchronous read behavior; keep the additive table for forward recovery. Do not run the down migration to clear unresolved obligations. No Asset schema/routes, runtime replica/pool settings or production data are changed.

## Evidence and remaining gates

Local fixtures cover 1,205 bindings, restart/wrap, whole-batch poison, global outage, repair fairness, package rebinding, capacity backpressure, lease takeover, stale writers and atomic rollback on real PostgreSQL constraints. Existing lifecycle projection fixtures cover retention extension and terminal/version fences. Hosted required CI remains mandatory.

Before C3b: pin CMS/Asset artifacts; run shadow comparison with new-ready and extended-retention rows becoming visible, insertions/policy changes during traversal, outage/recovery and rollback. Measure full-cycle lag, oldest repair age, DB statements/connection occupancy, HTTP calls/bytes, and peak CPU/memory against J0's accepted deadline and whole-platform budget. A normal tick has one Asset batch; repair adds up to 20 singleton requests. It is incorrect to count modeled read savings while the old read path remains enabled. No deployed acceptance or cost saving is claimed by this candidate.
